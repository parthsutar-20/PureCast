## 2. Common Operational Procedures

### 2.1 Starting the Complete Environment
```bash
# 1. Start all infrastructure containers
make up

# 2. Execute database migrations
make db-upgrade

# 3. Seed demo data (purifier units, cartridges, baseline history)
make seed

# 4. Start API server in development mode
make api
```

### 2.2 Database Migrations
```bash
# Create a new autogenerated migration after model updates
make db-revision MSG="add_cartridge_model_table"

# Apply pending migrations
make db-upgrade

# Roll back the most recent migration
make db-downgrade
```

### 2.3 TimescaleDB Maintenance
```sql
-- View telemetry hypertable chunk status
SELECT * FROM timescaledb_information.chunks WHERE hypertable_name = 'telemetry_readings';

-- Manually trigger compression of older chunks (> 7 days)
SELECT compress_chunk(chunk) FROM timescaledb_information.chunks 
WHERE hypertable_name = 'telemetry_readings' AND is_compressed = false;
```

## 3. Incident Response & Troubleshooting

### Incident A: MQTT Telemetry Ingestion Latency Spike
- **Symptoms**: Messages queueing up in broker, `purecast_telemetry_messages_total` ingestion rate drops.
- **Triage**:
  1. Inspect ingestor logs: `docker compose logs -f ingestor`
  2. Verify Redis responsiveness: `docker compose exec redis redis-cli ping`
  3. Check TimescaleDB connection pool exhaustion. Increase `DATABASE_POOL_SIZE` in `.env`.

### Incident B: False Alarm Flood on Cold Winter Mornings
- **Symptoms**: Spikes in `PREFILTER_CLOG` or `MEMBRANE_FOULING_SCALING` during temperature drops below 15°C.
- **Triage**:
  1. Check temperature compensation logs: verify $T_{water}$ thermistor readings are not frozen or dropped.
  2. The diagnosis engine should automatically tag `COLD_WATER_MORNING` and suppress alarms when corrected flow $Q_{norm}$ remains steady.
